# BL-004 Review finding classification / convergence: research report (worker R1)

## Summary

Facts first, then open questions. Nothing here freezes architecture.

1. At baseline the only classification a finding carries is a reviewer-declared severity (HIGH, MID, LOW). Adjudication is a mechanical count, the reviewer's severity is final, HIGH and MID block, LOW does not, and no finding has an identity, category, disposition or rationale. [CURRENT FACT]
2. Finding content is not durable: the report is copied only to the runtime area, and the canonical gate holds digests only (`result_digest`, `raw_report_set_digest`, `adjudication_digest`, `obligation_digest`). [CURRENT FACT]
3. Nothing resolves an obligation: both static Policies state "P2 resolves none" / "P3 resolves none". A false-positive HIGH or MID therefore has no dismissal route. [CURRENT FACT]
4. For planning, a not-authorized attempt ends `not_authorized` and an identical retry is a new Run that "does not remember the refusal". [FROZEN CONTRACT FACT]
5. For Work, a non-authorizing generation 2 leaves the START mutation pending in `ReconcileRequired`; reading the code, no path re-runs the executor or the reviewer afterwards. [INFERENCE]
6. The BACKLOG's four classes (VALID DEFECT, IMPROVEMENT, FALSE POSITIVE, REQUIREMENT CHANGE) appear in no frozen contract, canonical Skill, source file or test. [CURRENT FACT]
7. A different taxonomy exists in the non-normative design memos (Problem / Improvement x HIGH/MID/LOW; dismissal and HUMAN as adjudication outcomes) and disagrees with the BACKLOG on how an IMPROVEMENT is treated. [DESIGN MEMO]
8. The gate shape is pinned in code: one required slot per Policy, one accepted task per Run, at most 3 Work or 4 planning generations, one static Policy per kind. [CURRENT FACT] The frozen F3 contract also fixes one Candidate and written-once proof notes per START mutation. [FROZEN CONTRACT FACT] Any disposition, adjudicator or repair-loop design has to amend one of these pins or live outside the chain. [INFERENCE]
9. The roadmap memos place same-run recurrence in P4 and durable Finding/Repair history in P5, while frozen P1 R3 s10 requires gate or provenance facts relied on after clone or process loss to reach committed local Git state before the dependent external launch or terminal boundary. Whether a disposition or recurrence fact counts as such a fact is the main structural question for P4. [INFERENCE]

### 3.2 Strengths (evidence-supported)
