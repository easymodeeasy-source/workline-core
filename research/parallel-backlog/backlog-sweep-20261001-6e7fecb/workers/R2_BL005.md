## 5. Privacy and public-repository implications

### 5.1 What a Project repository would receive

- [CURRENT FACT, measured] **Result bytes, duplicated.** The Candidate snapshot carries the full base64 bytes of every file/symlink result entry, committed in the generation-1 commit before the reviewer runs. For an authorized Work the same bytes later also appear in K1; for a **not-authorized** Work they exist in the repository history only inside the snapshot (measured with a rejected file).
- [FROZEN CONTRACT FACT] F2 section 9.6: "No contract-level maximum payload size is imposed", and the reconstruction criterion forbids moving K1 earlier to avoid duplication. Arbitrary binary content is supported (F2 section 9.4.2).
- [INFERENCE] With a remote, those commits are ancestors of every later commit on the branch, and `registry.md` "Push destination" says a recorded push publishes that commit together with the history it was built on. A rejected Work's snapshot would therefore reach the destination with a later push of that branch. (This follows F3 section 4.3: commits "reach the destination as the history of the next authorized push".) Without a remote nothing is published.
- [CURRENT FACT] **TaskInput** repeats the whole Candidate and the Context: Work name, display, branch name, paths, the executor's commit message, authority file digests, a content identity of the running implementation. [INFERENCE] Mostly already committed elsewhere (Work file, K1), so low incremental disclosure; the message text is the free-form part.
- [CURRENT FACT] **Reviewer identity and version** are caller-declared single-line strings written to the TaskInput and the accepted descriptor (`work_review._persistable_reviewer_text`).
- [CURRENT FACT, measured] **Reviewer finding text** (which may quote paths, code or secrets the reviewer saw) is runtime-only and untracked; it is not ignored by Workline (`registry.md` Git: Workline does not write ignore files), so it appears as untracked noise (`??`) and could be committed by an unrelated `git add`. Durable copies exist only as digests.
- [CURRENT FACT] **Events and Consumption** hold ids and a commit sha only.
- [CURRENT FACT] **Derivation detail** and the **result commit message** are caller free text and already committed on the legacy path.
